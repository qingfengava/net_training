## 运动模糊的对齐修正

旧算法在任意整数尺寸的核上绘制整数端点线段。偶数核中心与 OpenCV 默认锚点不一致；线段端点舍入也能令部分奇数核不对称。

centered_v1 使用奇数支撑域，在连续线段上采样，通过双线性权重分配到核网格，再强制核与其中心翻转的平均，归一化后显式使用中央锚点。配置的长度仍可取 2～9，偶数长度无需删除；长度控制线段跨度，不再直接决定矩阵边长。

该修正适用于新烘焙，不会修改已有 PNG 或历史标签。11-05 起新清单的 bake_version 为 3，加入拜耳取样和频闪后升为 4；没有任何代码读这个版本号，历史复现靠的是清单里保存的完整配置（缺 kernel、flicker、bayer 键就走旧路径）。

历史清单的 effects.motion_blur 没有 kernel 字段时，prepare_view 仍执行原 legacy_v2 路径，保持随机序列、舍入及操作顺序。复现旧实验时应读取其原清单中的整个配置，不能把今天的默认配置合并进去。也可显式指定 kernel=legacy_v2，仅用于历史对照。

## 预测 ROI 扰动

这个模块模拟网络看到的窗口分布，不运行 sleepy 跟踪器，也不增加部署推理次数。合成路径用当前装甲为位置和尺度参照，采样整车装甲包络的近似大小，再施加预测残差；未宣称已经复现连续跟踪误差。

默认状态抽样：

| 状态 | 概率 | 输入 |
|---|---:|---|
| 搜索 | 35% | 全图 |
| 巡检 | 5% | 全图 |
| 短暂恢复 | 20% | 带较大误差和扩窗的 ROI |
| 稳定跟踪 | 40% | 带预测残差的 ROI |

状态比例是待校准的实验设置，巡检是计划中的部署策略，不代表 sleepy 当前已经实现巡检。非 4:3 源图的“全图”会使用能容纳的最大居中 4:3 区域。

- 包络尺度：装甲投影宽高包络的 2～5 倍；普通目标再扩 1.4 倍，基地扩 3 倍。没有实例 ID 时不按编号把不同机器人错误地合并。
- 时间间隔：稳定状态 2～20 ms，恢复状态 20～300 ms。
- 位置误差：包络尺度相关的高斯误差，加上“速度预测误差 × 时间间隔”。速度误差以画幅/秒配置，再换算为原图像素/秒。
- 尺度误差：对数尺度随机偏差；恢复时位置误差随时间增加。
- 窗口按 lost_time_ms=1500 线性扩大到最大范围；超时或预测中心离开图像时回全图。这与现有 sleepy 时间扩窗机制对应，后续改变运行时回退阈值时应同步调整数据配置。
- 输出保持 4:3，触边时平移窗口，适配本项目 768×576 输入。它不照搬旧 RP 分支的最终正方形窗口。

预测窗口不以当前真值是否成功覆盖目标作为重抽条件。与窗口相交的装甲保留标签，出窗角点的 vis 设为 0；完全没有面交集的目标才移除。这样允许部分截断和真实漏裁，不把半块装甲当作无标注背景。严重截断的类别可辨认性仍应在数据审核时检查。

### 使用回放预测包络

仿真样本可在 canonical 的 scene.roi_prediction 中提供外部预测，替代随机误差路径：

~~~json
{
  "image_size": [1440, 1080],
  "bbox": [620.0, 420.0, 820.0, 560.0],
  "age_ms": 18.0,
  "state": "tracking",
  "is_base": false
}
~~~

bbox 是当前图像时间、原图像素边缘坐标下的预测包络 [x0,y0,x1,y1]，尚未进行固定扩边和时间扩窗；不能直接填最终 ROI。state 支持 tracking/recovering/search/patrol。记录应由回放或采集适配层生成，当前普通 sleepy 日志不会自动转换成这些字段。本入口仍遵循仿真源与训练分区限制。

如果同一帧又开启新增镜头畸变，包络的坐标系就不一致，因此明确报错，不猜测变换。meta.jsonl 中的 roi_augmentation 保存来源、状态、时间、预测误差及边界平移。

## 点阵与相机采样产生的摩尔纹

实现为 dot_sampling_residual_v1，在已渲染图像上叠加有采样依据的有限幅度亮度残差：

1. 根据装甲四角点建立平面到图像的单应变换，得到点阵相位和局部投影频率。
2. 用有限傅里叶展开表示方点或圆点网格。
3. 用高斯光学传递函数衰减高频，并用像素孔径的 sinc 响应积分。
4. 在原图像素中心采样，由超过奈奎斯特频率的成分形成混叠，再将有限幅度增益应用到亮屏区域。

这不是直接覆盖几条固定频率条纹。倾角、距离、点阵布局、相位、光学模糊和像素孔径都会影响纹理。光学模糊足够强或点阵非常小时，模型会自然衰减，可能没有可见变化。

默认强度 0.15～0.35，光学 σ 为 0.15～0.45 原图像素，像素孔径为像素间距的 0.6～1.0。每通道使用相同亮度增益；不移动角点，不人为改变红蓝类别。熄灭屏和带遮挡标记的装甲跳过，避免在遮挡物上绘制点阵。增强先作用在原分辨率裁剪图，然后继续现有曝光、光晕、模糊、噪声和最终缩放。

默认从 scene.screen 的 look 读取实际行列数和点形状。若没有屏幕元数据，或者同帧有不同点阵布局且无法关联到各块装甲，会记录原因并跳过，避免将 B 的 64×48 强加到 A 上。已知数据集布局时可显式设置 grid_source=config，用 grid 和 dot 指定；填充率仍从配置范围抽样。

它是亮度残差近似：输入已经经过仿真渲染，无法恢复丢失的子像素字形；它只改亮度，不产生伪色，也不模拟显示刷新。伪色由下面的拜耳取样产生，刷新条纹由全局快门频闪产生；两者与摩尔纹可以同时开启。是否提高实拍精度，必须使用独立相机会话验证。

effects.moire 保存点阵、相位、填充率、光学参数、增益范围及实际改变的像素通道数。images_with_moire 统计在这一增强步骤确实改变了值的图像数；后续模糊和量化可能进一步减弱变化。

## 拜耳取样与去马赛克：伪色

海康相机输出 BayerRG8（RGGB），sleepy 在 GPU 上用 NVIDIA NPP 的 `nppiCFAToRGB` 去马赛克。每个像素只有一个颜色通道，红、蓝通道每两个像素才采一次。点阵的点比两个像素更小时，点和滤色阵列互相混叠，产生亮度条纹和**伪色**。颜色是我们的标签，所以这一项比摩尔纹更要紧。仿真器渲染的是每个像素都有完整 RGB 的图，天然没有这个现象。

`effects.bayer`（默认关闭）让整帧走：RGB → RGGB 取样 → 双线性去马赛克。放在 `apply_effects`（曝光、模糊、噪声）之后，对应真实链路里 8 位 Bayer 数据产生之后。红色位点的相位取 ROI 左上角在整帧里的奇偶，因为真实的去马赛克在整幅 1440×1080 上做，之后才裁 ROI。只改像素值，不移动几何，所以标签逐字节不变。

**去马赛克用双线性，是对 sleepy 实际用的 NPP 实测之后选的：**
- 在本机用 ctypes 直接调用 `nppiCFAToRGB_8u_C1C3R_Ctx`（RGGB，`NPPI_INTER_UNDEFINED`，和 `cvtcolor.cu` 的参数一致），测脉冲响应：红、蓝位点是 `[.25 .5 .25; .5 1 .5; .25 .5 .25]`，绿位点是十字形 `[.25 / .25 1 .25 / .25]`，和双线性核完全相同；边界脉冲响应与反射 101 边界一致。输出通道顺序是 R、G、B。
- 但 NPP 不是纯双线性：在强边缘处它按方向选插值。与本实现的像素差：白噪声图平均 5/255、最大 110；红色点阵（点距 3 px）平均 1.1/255；对角条纹 0.02/255；竖直红黑边平均 0.04/255、最大 10。点阵这类关心的图像上差别很小，白噪声上较大，不要把它当作 NPP 的逐像素复现。

**噪声顺序：不需要把噪声搬进马赛克。** 真实传感器的噪声产生在每个传感器像素上，先于去马赛克。曾经担心现在的顺序（先在 RGB 三通道里加噪声，再取样去马赛克）会把噪声滤掉，实测并不是这样：取样只保留每个位点的一个通道，两种顺序在数学上等价，去马赛克后的噪声标准差都是原来的 0.75（红、蓝）和 0.79（绿）倍，与双线性核的理论值一致（`sqrt((1+.5+.5+.25)/4)=0.75`，`sqrt((1+.25)/2)=0.79`）。`tests/test_bake_augment.py` 里固定了这个事实。去马赛克后的噪声带颜色、空间相关，这一点真实相机也一样。

**效果（噪声、模糊、泛光关闭，30 个样式 B 视图）：** 平坦区域的像素一个都不变（0.000%，覆盖 2000 万像素），变化全部在点阵和边缘等有高频结构的区域（其中 7.8% 的像素变化超过 8 级，最大 246）。在红色点阵（点距 3 px）上，约 40% 的暗背景像素获得了蓝色，红点最多被抹掉整个红色值。灰色物体的锯齿边缘出现彩虹色像素。

**局限：**
- 只支持 RGGB 和双线性。海康以外的相机或其他网格需要改 `pattern`，目前被校验拒绝。
- 不模拟 ISP 的其他环节（色彩校正矩阵、相机内的 gamma、锐化）。sleepy 的相机配置里 `gamma: 0.7` 后面注释着“Bayer用不了”，说明在 BayerRG8 输出下这个参数不起作用；相机内部是否还有别的处理没有核实。
- 没有用实拍验证伪色的强弱。

`effects.bayer` 保存取样相位、网格和去马赛克方式；`images_with_bayer` 统计命中的图像数。

## 全局快门下的频闪

LED 点阵屏一般按行扫描、用 PWM 调光。相机是全局快门（所有像素同时开始、同时结束曝光），所以没有滚动快门那种斜条纹，但曝光窗口 T 里含几个刷新周期，决定了每一行收到多少光。

**模型（`effects.flicker`，默认关闭）：** 屏的第 r 行（共 N 行）的 PWM 是周期 1/f、占空比 d 的方波，相位 `scan_phase + scan_span · r/N`（以刷新周期为单位）。曝光窗口 `[t0, t0+T]`，t0 每帧随机。行 r 收到的光，是方波在窗口内的积分，闭式解，再除以 `d·T·f` 归一化，使期望值为 1：

```
gain_r = [F(T·f + t0·f − shift_r) − F(t0·f − shift_r)] / (d · T · f),   F(t) = floor(t)·d + min(t − floor(t), d)
```

- 曝光含**整数个**刷新周期（`T·f` 为整数）时，所有行 gain 恒为 1，没有频闪。`tests` 里精确检验了这一点。
- 不足一个周期时，各行相位不同，亮度在 0 到 1/d 之间跳变；`T·f = 0.36` 时最暗的行完全熄灭、最亮的行是 1/d 倍。
- 一帧里所有屏共用同一个曝光起点（全局快门同时开始曝光）；每块屏有各自的扫描相位，`synchronized: true` 时共用同一个。
- 增益作用在线性光里，所以亮笔画如果已经接近满刻度，会被限幅在 255，条纹对比度被压平；频闪主要体现在暗到中等亮度的区域。这与真实传感器的行为一致。
- 仿真器已经画了暗带的屏（`screen_state == flicker`，8% 的装甲）、熄灭屏和被遮挡的装甲不叠加。

**用实测值填参数：** 官方模块出来之后，需要测的量和对应的配置键：

| 要测的量 | 怎么测 | 配置键 |
|---|---|---|
| 刷新频率 f | 用极短曝光（如 100 µs）拍一组，数画面里明暗条纹的间距与扫描节奏；或用示波器/光电二极管 | `refresh_hz` |
| PWM 占空比 d | 同上，亮时间占周期的比例 | `duty` |
| 扫描方式 | 极短曝光下条纹是否整屏同亮灭（`scan_span: [0, 0]`），还是自上而下/自下而上扫过（`scan_span` 接近 1，`scan_direction` 取 `down` 或 `up`） | `scan_span`、`scan_direction` |
| 实际曝光时间 | 读相机配置，比赛用 `exposure_time`；自动曝光会在 0.1～3.5 ms 之间变化 | `exposure_ms` |
| 屏的行数 | 点阵规格 | `grid_source: scene` 自动读取，或 `rows` |

默认范围（`refresh_hz` 240～4000 Hz、`duty` 0.15～0.9、`exposure_ms` 0.5～3.5、`scan_span` 0～1）是占位的宽范围，不是实测。`T·f` 的分布跨度很大（采样到 0.25 到 11 个周期），既有重频闪也有几乎无频闪的样本。

**局限：**
- 没有模拟相机的触发与屏的刷新是否同步。同步时每帧的条纹位置固定，不同步时每帧随机，目前按随机处理。
- 整屏亮度的帧间变化只留了一个 `frame_sigma` 接口，默认 0（自动曝光会补偿平均亮度）。
- 没有模拟 PWM 的上升/下降沿，也没有模拟不同颜色（红、蓝）LED 的不同扫描相位。
- 没有用实拍验证。

`effects.flicker` 保存刷新频率、占空比、曝光时间、曝光起点、`T·f`，以及每块屏的扫描相位、扫描跨度、方向和行增益的最小/最大值；`images_with_flicker` 统计确实改变了像素的图像数。

## 现有模型对这两种伪影有多敏感（2026-11-06，不训练）

把同一份样式 B 验证集（579 张）配对地烘焙成带伪影的版本（同种子，曝光、噪声、ROI 的随机流不变，脚本逐张核对标签、ROI 和其余效果参数一致），用没见过这些伪影的现有模型评估。脚本和全部评估结果在 `runs/verification/bake_artifacts_20261106/`（`sensitivity.py`、`sensitivity/summary.md`）。下表是当前 B 候选 `b_from_a_e100_s0`，括号是 AP50 相对标准验证集（0.9149）的变化；`abl_base_s0`（11-06 消融的基线）方向一致，数字见 summary.md。

| 输入 | AP50 | 机器人类别准确率 | 熄灭召回 | 角点 P95 | 误检 |
|---|---:|---:|---:|---:|---:|
| 标准验证集 | 0.9149 | 0.9026 | 0.764 | 4.79 | 281 |
| 拜耳取样 | 0.9039（-0.011） | 0.8867 | 0.736 | 5.02 | 304 |
| 频闪 300 Hz、曝光 1.2 ms（0.36 个周期） | 0.7513（**-0.164**） | 0.6602 | 0.771 | 9.77 | 389 |
| 频闪 1000 Hz、曝光 1.5 ms（1.5 个周期） | 0.9074（-0.008） | 0.8909 | 0.764 | 4.82 | 281 |
| 频闪 3000 Hz、曝光 1.5 ms（4.5 个周期） | 0.9136（-0.001） | 0.9001 | 0.764 | 4.80 | 279 |
| 频闪，默认范围 | 0.8910（-0.024） | 0.8710 | 0.764 | 5.35 | 295 |
| 拜耳 + 频闪默认范围 | 0.8746（-0.040） | 0.8562 | 0.736 | 5.41 | 305 |

- **拜耳：** 掉 0.011–0.015 AP50、1–1.6 个百分点机器人类别准确率，两个模型一致。同一个模型、同一批图，差距是增强本身造成的，不是训练噪声（重训噪声约 0.003）。熄灭召回在 `abl_base_s0` 上掉了 8 个点，但只有约 12 个样本，不要当作确定的数。
- **频闪的影响取决于 `T·f`，跨度极大：** 4.5 个周期几乎无影响，0.36 个周期时机器人类别准确率掉 24 个百分点、角点误差翻倍。这时一部分行整段熄灭，笔画在图像里真的缺了，增强也只能让模型对缺行更宽容，补不回丢失的信息。
- **默认范围平均掉 0.024，是被重频闪的尾部拖下来的。** 它的占空比下限 0.15 会给出最高 6.7 倍的行增益，对真实模块未必有意义。
- **仿真里的结论。** 真实镜头的光学低通可能让混叠比这里弱，也可能更强；没有用实拍验证。

**这对决策的含义：** 拜耳肯定会发生（真实相机每一帧都有），且已经测到约 1 个点的损失，值得训练时加；频闪能否发生、多重，要看官方模块，而且曝光时间可以直接避开它——曝光取刷新周期的整数倍时每一行增益恒为 1（`T·f` 为整数）。注意 sleepy 的自动曝光是连续调节的（日志里 2240、2401、2531 µs…），没有量化到刷新周期的整数倍，要避开频闪得改成量化步进；这是 sleepy 侧的事，这里没有改。

## 拜耳取样的验证训练（2026-11-06）

用户批准后只再训一组：训练集每张仿真图都过拜耳（`configs/bake/bayer.yaml`，概率 1.0），其余与基线 `abl_base_s0` 完全相同（同一份样式 B 数据、种子、A 初始权重、`pose_transfer_ab.yaml`、30 轮）。脚本 `scripts/run_bayer_validation.py`，结果 `runs/experiments/bayer_validation_s0/comparison.md`。训练集与基线逐张配对核对：ROI、窗口模式、其余效果参数、标签完全相同，5224 张全部带拜耳记录，所以两组只差拜耳这一步。两个模型都在两份验证集上评估：标准验证集（没有拜耳）和拜耳验证集（`configs/bake/bayer_val.yaml`，同一批验证图过一遍拜耳）。判定标准在看结果前写进脚本。

| | 基线 | 拜耳训练 | 差 |
|---|---:|---:|---:|
| 标准验证集 AP50 | 0.8975 | 0.8943 | -0.003 |
| 标准验证集 机器人类别准确率 | 0.8832 | 0.8842 | +0.1 点 |
| 拜耳验证集 AP50 | 0.8823 | 0.8888 | **+0.0065** |
| 拜耳验证集 机器人类别准确率 | 0.8737 | 0.8672 | -0.65 点 |
| 拜耳验证集 召回 | 0.9081 | 0.9205 | +1.2 点 |
| 拜耳验证集 熄灭召回（约 144 个样本） | 0.6389 | 0.7361 | +9.7 点 |
| 拜耳验证集 误检 | 384 | 408 | +24 |
| 拜耳验证集 <8 px 检出且分类正确 | 0.5723 | 0.5755 | 持平 |

- **预先定好的判定：追回比例 0.43，“部分追回，需要第二个种子确认”；标准验证集上在容差内。** 追回比例 = 拜耳训练模型在拜耳验证集上多拿的 AP50 / 基线在拜耳验证集上损失的 AP50（0.0065 / 0.0152）。
- **收益主要在“找到装甲”，不在“读对编号”。** AP50、召回上升，熄灭召回回到了标准验证集的水平，但颜色加编号的类别准确率没有变好（-0.65 点，在噪声范围内），小目标的类别准确率也没有改善。拜耳混叠丢掉的是点阵的细节，模型能变得更宽容，补不回丢失的信息。
- **熄灭召回的 +9.7 点只对应约 14 个样本**，不要当作确定的效果。
- **没有看到伤害：** 标准验证集上 AP50 -0.003（重训噪声约 0.003）、机器人类别准确率 +0.1 点、角点 P95 +0.12 px。
- 单个种子；拜耳验证集与训练增强同源，真实相机上的效果仍未验证。
- 脚本复用了 `run_bake_ablation.py`。训练的不可回收内存实测约 5.5 GB（anon 4.2 + shmem 1.3 GB），6 GB 上限只有约 0.5 GB 余量，7 GB 才宽松，见交接文档。

## 消融结果（2026-11-06）

四组使用同一份样式 B 数据（`style_b_train` + `style_b_val`）、同一烘焙种子 0、同一 A 初始权重（`y26n_simm7_e100`）和同一训练配置（`pose_transfer_ab.yaml`，30 轮，种子 0），只有烘焙配置不同。复现与完整表格：

~~~bash
python scripts/run_bake_ablation.py --dry-run       # 只列出 23 步命令，不执行
python scripts/run_bake_ablation.py                 # 串行执行（每步内部经 run_capped.sh），可续跑
python scripts/run_bake_ablation.py --report-only   # 只重新生成报告
~~~

报告：[comparison.md](../runs/experiments/bake_ablation_v3_s0/comparison.md)。三份验证集分别是新标准验证集（579 张，四组逐字节相同）、合成压力验证集（`configs/bake/ablation_stress_val.yaml`，增强也作用于验证）和 A→B 实验的旧验证集。新标准验证集上，相对修正核基线（AP50 0.8975）：

| 组 | AP50 | 误检数 | 熄灭召回 | 机器人类别准确率 |
|---|---:|---:|---:|---:|
| 仅预测 ROI | 0.8837 | 413（+35） | 0.681（-4.2 点） | 0.8825（持平） |
| 仅摩尔纹 | 0.8999 | 382（+4） | 0.736（+1.4 点） | 0.8789（-0.4 点） |
| ROI + 摩尔纹 | 0.8843 | 432（+54） | 0.667（-5.6 点） | 0.8788（-0.4 点） |

- **预测 ROI 有害，但原因多半是训练数据的分布变了，不是窗口这个想法本身。** 三份验证集上 AP50 都低 0.008–0.014，超出预设容差（0.01）；多出的误检几乎都是落在真实装甲上的重复框或松框。预测窗口更紧：训练集装甲标注少 7.3%，宽度中位数从 17.6 增到 22.6 px，宽 ≥64 px 的占比从 11.3% 增到 18.3%，8–32 px 的中小装甲少约 8 个百分点。验证集是全图或随机窗口，两者分布不一致。
- **摩尔纹没有看出害处，也没有看出收益。** 摩尔纹步骤真的改变了像素的图只有 821 张（训练图的 15.7%），所以结论只适用于这个实际强度。验证集里没有摩尔纹，最好的结果就是持平；对真实相机有没有用，要用代理屏或实拍会话验证。
- **噪声参照：** 修正核基线与旧模型相比，AP50 差 0.003，机器人类别准确率差 0.4 个百分点，熄灭召回差 1–3 个百分点（样本约 144 个）。差距在这个范围内不要当作增强的效果。单个种子，训练没有开确定性模式。
- **压力验证集对没见过增强的模型也不难**（旧模型 AP50 0.888，标准验证集 0.900），ROI 组在这里同样没有占优，所以没有仿真证据说明预测 ROI 增强对现有模型有帮助。该集目标数（1513）和标准集（1610）不同，两张表的数字不要互相比较。

后续：要继续研究预测 ROI，先让训练集的尺寸分布与验证一致（提高全图和搜索状态的比例，或补中小目标），再用同样的脚本重做；要确认“ROI 有害”，补第二个种子只重训基线和 ROI 两组即可。两者都要先拿到训练授权。
