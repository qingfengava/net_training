## 固定输入与结果

- 权重：`runs/train/b_from_a_e100_s0/weights/last.pt`，SHA256 `6ba72467b53dada955df5c9f686f2ec8be3f253db4015d4d9ac52c5e1d7a8abe`。
- 数据：`baked/style_b_v1` 的独立 B 验证分割，先对全部 579 张图重跑历史 e2e 评估，复现 `<8 px` 的 318 个目标、263 个匹配、201 个正确，即 55 个未匹配和 62 个类别错误。
- 在包含这些目标的 119 张图上，用原烘焙种子重建缩放前的退化图像；再次缩放与保存的网络输入逐像素一致。三条路线共享这些原始分辨率像素，没有重新采样噪声或模糊。
- 核心对照是 314 个历史全图目标；另 4 个来自历史 ROI，只在其原有可见区域内对比，并在报告中单列。所有目标在放大后仍留在原分母内。
- 匹配继续使用 `nt.eval` 的置信度 0.2、一对一、类别无关 IoU >=0.5；同一图的所有标注目标参与匹配竞争。

| 路线 | 匹配 / 318 | 正确 / 318 | 匹配后类别准确率 | 检出且类别正确 / 全部 |
|---|---:|---:|---:|---:|
| 历史输入 | 263 | 201 | 76.43% | 63.21% |
| 真值 ROI | 295 | 268 | 90.85% | 84.28% |
| 检测驱动 ROI + 全图 | 299 | 267 | 89.30% | 83.96% |

仅看主要的 314 个历史全图目标，正确数分别为 199、266、265，比例为 63.38%、84.71%、84.39%。
红蓝 1/3/4 数字目标共 129 个，正确数为 69、103、105，比例为 53.49%、79.84%、81.40%。
所有“类别正确”均要求合并类别正确，即颜色及编号同时正确。

真值 ROI 恢复 79 个历史失败，同时让 12 个历史正确目标变错；检测路线恢复 70 个、退化 4 个，净增加 66 个正确目标。
检测路线同时保留全图回退，因此某些指标超过真值 ROI 并不矛盾：后者是每个目标单独裁剪的诊断路线，并非所有策略的理论上限。

## ROI 策略与代价

窗口保持 4:3，最小宽 384 原图像素，宽度按目标框包络乘 16 决定，上限为可见图像范围；输入为 768×576。

- 真值路线用目标真值框选择窗口，仅供诊断。
- 检测路线只接受全图预测作为输入：候选置信度 >=0.1，网络框宽 <16 px，按置信度排序，重叠窗口去重，最多 4 个窗口。真值不参与候选选择。
- 检测结果映射回历史输入坐标，按置信度、IoU 0.5 跨类别合并。无候选时保留全图结果；不裁掉统计分母。
- 完整覆盖 288/318 个极小目标。119 张图中，82 张执行了 1 次全图 + 4 次 ROI 推理。

本机 RTX 5060 Laptop、PyTorch FP32、batch=1、预热后同步计时：

| 路线 | P50 | P95 | P99 |
|---|---:|---:|---:|
| 全图路径 | 6.495 ms | 7.233 ms | 7.570 ms |
| 全图 + 检测 ROI | 28.515 ms | 30.727 ms | 32.778 ms |

计时包含缩放、预处理、设备传输、网络和后处理；不含载盘、合成图重建及报告输出。这不是 TensorRT 或整条自瞄系统的延迟。

**误检需要使用同样的后处理比较。** 原始 e2e 全图在这 119 张图上有 176 个误检；仅给全图加相同去重后降至 41 个，正确目标数为 200/318；检测 ROI 合并后有 101 个误检。
因此不能把 176→101 宣称为裁剪降低误检：相对同样去重的全图，加入 ROI 增加了 60 个误检。该补充对照完全复用已有预测，没有额外推理。

当前结论是：固定权重下，调整尺度与上下文能恢复相当一部分识别能力；同时增加计算量和误检。不能仅凭此证明错误全来自下采样，也不能直接推断真实相机收益。
下一步应检查新增误检和 4 个退化目标，再考虑更少的 ROI、时间上的调度及结果融合。当前策略尚未接入 sleepy。

## 如何审核案例

用浏览器打开 `index.html`，默认隐藏真值与预测。每个目标提供：原图像素、原分辨率增强后、历史网络输入、真值 ROI 输入、检测 ROI 覆盖窗口。
PNG 裁块保留原始像素，页面使用最近邻放大；没有锐化或超分辨率。目标位于局部视图中心附近。

1. 先填写原图可辨认性：可辨认、存在歧义、无法辨认，或保留未判断。
2. 根据原图、退化和输入之间的变化，多选可能原因并填写证据；原因可以重叠。
3. 再显示真值与预测，检查定位偏差、编号/颜色混淆及 ROI 前后变化。
4. 导出审核 JSON 留档。浏览器本地缓存方便继续审核，换浏览器或清缓存时请导入导出的 JSON。

所有 117 个失败都进入图库。50 个正确对照是在运行 ROI 前按类别、原输入宽度分层并分散图像选择的；只有其中 2 个碰巧属于后续检测 ROI 的 4 个退化目标。全部退化目标仍在 `targets.jsonl` 中。
可辨认性与具体原因均保留 `pending`，未自动把模型恢复当作人工结论。`browser_checks/tiny_reviews.json` 是浏览器功能测试产物，包含明确标记的测试备注，不是人工审核结果。

## 复现

在项目根目录运行，输出目录必须不存在：

```bash
scripts/run_capped.sh 5 -- python -m nt.tiny \
  --out runs/experiments/tiny_b_v2
```

默认沿用本次权重、数据、阈值、ROI 参数及控制样本种子。可用 `--help` 查看参数。
改变 ROI 参数应使用新的输出目录；不改变模型权重。历史评估的权重/数据哈希或基线数量对不上时会报错。

仅更新报告和去重对照，不重跑推理：

```bash
.venv/bin/python -m nt.tiny --out runs/experiments/tiny_b_v1 --report-only
```

主要文件：

| 文件 | 内容 |
|---|---|
| `inputs.json` | 原始输入、权重、代码哈希和运行参数 |
| `baseline_check.json` | 与历史极小目标计数的对拍 |
| `baseline_predictions.jsonl` | 579 张验证图的原始预测 |
| `targets.jsonl` / `targets.csv` | 全部 318 个固定目标的逐目标结果 |
| `frames.jsonl` | ROI 窗口、预测、合并结果、误检和时延 |
| `pixel_checks.jsonl` | 119 张图的像素一致性与来源哈希 |
| `cases.json` / `cases/` / `index.html` | 167 个审核案例及图片 |
| `summary.json` / `comparison.md` | 指标、子集、恢复/退化及局限 |
| `report_refresh.json` | 后续报告更新代码哈希；保留原推理指纹 |
